# Multi-Agent Research Assistant

A 5-agent research pipeline built with CrewAI. It answers questions from ingested documentation, checks every claim's quote against the source text, and returns a report with a per-claim evidence table. If the documents don't cover a question, it says so instead of guessing.

**Stack:** CrewAI, ChromaDB, FastAPI (async job API), Streamlit, Groq / OpenAI via LiteLLM

## How it works

1. **Planner** (LLM) breaks the question into sub-questions.
2. **Retriever** (plain Python, no LLM) searches ChromaDB for the question and each sub-question.
3. **Researcher** (LLM) drafts claims, each with an exact quote and a chunk ID.
4. **Quote check** (plain Python) drops any claim whose quote is not found in the cited chunk.
5. **Verifier** (LLM) judges each remaining claim against its quote: VERIFIED, PARTIALLY SUPPORTED or UNSUPPORTED. Claims with promotional wording (e.g. "leading", "production-ready") that aren't attributed to the documentation are downgraded to PARTIALLY SUPPORTED by a code rule.
6. **Writer** (LLM) writes the report from the surviving claims only.

The Gaps and Evidence sections are generated by code, not by the writer, so the model cannot hide missing evidence.

## Features

- Async API: `POST /research` returns a job ID, `GET /research/{job_id}` is polled for the result
- One pipeline run at a time, with a queue limit, to protect rate limits
- Streamlit UI with example questions, history, clear, report download and run metrics
- Switchable LLM provider (`LLM_PROVIDER=openai` or `groq`) with retry handling for rate limits
- Every run saves its intermediate files (plan, chunks, claims, verdicts) under `runs/` for debugging

## Project structure

```
agents/      agent definitions (planner, retriever, researcher, verifier, writer)
api/         FastAPI app (async job endpoints)
crew/        pipeline.py (main flow), tasks.py, crew_config.py
data/        source PDFs and the ChromaDB index
frontend/    Streamlit app
tools/       ingest.py, vector_store.py, llm_config.py
```

## Run locally

1. `pip install -r requirements.txt`
2. Create a `.env` file (never commit it):
```
   OPENAI_API_KEY=your_key
   GROQ_API_KEY=your_key
   LLM_PROVIDER=openai
```
   Set `LLM_PROVIDER=groq` to use the free Groq tier instead.
3. Start the API: `uvicorn api.main:app --port 8000`
4. Start the UI: `streamlit run frontend/app.py`

## Tests I ran

| Test | Result |
|---|---|
| "what is crew ai?" | Report with an evidence table; every claim cites a chunk |
| "who won the 2022 football world cup?" (out of scope) | No evidence retrieved, no report written, gaps listed, finished in 46s |

Run time for in-scope questions varied from about 3 to 8 minutes, mostly from rate-limit waits on the free Groq tier and the number of claims extracted.

## Known limitations

- The knowledge base is two CrewAI documentation PDFs; PDF upload from the UI is not built yet
- `MIN_RELEVANCE` is set low (0.1), so weakly related chunks can pass retrieval on questions that are close to, but not covered by, the documents
- The number of claims varies between runs of the same question
- Verdicts come from an LLM judge plus two code rules; they are not a guarantee of correctness
- Job state is in memory: run a single server process, and jobs are lost on restart
- Not deployed yet
